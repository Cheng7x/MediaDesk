# 架构与工程不变量

本文件约束实现和重构，描述目标行为，不表示已经实现。表与组件按 [PRODUCT](PRODUCT.md) 的阶段逐步加入。

## 1. 结构与状态归属

默认单仓库、模块化单体，媒体处理最终以独立 worker 进程运行，避免转码资源挤占 API。M0/M1 一个 Spring Boot 模块按业务分包即可；M3 先跑单 worker，M4 再拆 API/worker Maven 模块，不能让生产 API 请求线程承担转码。

预期目录（尚非当前目录清单）：

```text
backend/                 M0 先单模块，按业务边界分包
  mediadesk-core/         M4 必要的领域、持久化与共用契约
  mediadesk-api/          M4 HTTP、鉴权、业务入口、发布与补偿
  mediadesk-worker/       M4 消费、任务执行与媒体进程
frontend/                Vue 应用
infra/                   Compose、Nginx、监控
docs/                    契约、决策、运行说明、实验证据
```

共用模块只共享实际被两类进程使用的契约与基础实现；不能因名字叫 core 就集中全部业务代码。

| 介质 | 职责 | 不能承担 |
| --- | --- | --- |
| MySQL | 成员、资源归属、配额、上传、任务、版本、审核等持久业务状态 | 保存大文件字节 |
| 私有对象存储 | 原文件、封面、预览、尝试输出 | 单独决定业务完成或授权 |
| RabbitMQ | 工作通知与分发 | 唯一任务记录或最终成功依据 |
| Redis | M6 共享会话、限流、元数据缓存 | 唯一配额/任务事实、最终资源授权决定 |
| SSE | 已鉴权的进度提示 | 唯一状态记录或可靠消息总线 |
| Elasticsearch | v1.1 可重建搜索视图 | 授权事实、原始业务记录 |

外部 IO、转码和长等待不放在数据库长事务内。事务覆盖一组必须同时成立的业务写入；跨系统操作显式设计中间态、重试与补偿。

## 2. 领域约束

| 领域 | 必须维护的约束 |
| --- | --- |
| User / Workspace / Membership | 同空间同用户成员关系唯一；当前成员关系是授权依据；唯一 Owner 不能被意外移除 |
| Asset / AssetVersion | 素材属于一个空间；素材内版本号唯一；版本身份和原文件不可覆盖，处理状态和派生结果可受控更新 |
| UploadSession / UploadPart | 绑定上传者、空间、预期大小、稳定 key、存储 uploadId 和过期时间；会话内分片号唯一 |
| ProcessingJob / ProcessingAttempt | 版本+处理类型/规格构成唯一业务任务；每次尝试保留独立 token、时间与失败分类 |
| OutboxEvent | 业务变更同事务写入；有 eventId、实体修订号和发布状态，允许重复投递 |
| Comment | 绑定固定版本；视频时间偏移为毫秒，非负且不超过已验证时长 |
| Review | 绑定固定版本及轮次；素材最多一个活动轮次，结论变更受并发条件保护 |
| ShareLink | 固定已通过版本、能力、期限和撤销状态；数据库仅存令牌摘要 |
| AuditEvent / Notification | 记录必要关键动作和站内提醒；与关键状态一致，避免敏感原文和无限数据增长 |

ID 用数据库生成 ID 或标准 UUID，按当前用途选择。约束由数据库和服务端共同保证；“先查再写”而没有约束或条件更新，不能作为并发保证。

## 3. 上传与配额（M2）

建立会话并预留配额 → 指定对象/分片的短期签名直传 → 核对成功分片 → 请求完成 → 服务端核对存储结果 → 创建版本与后续持久任务。

```text
UPLOADING → COMPLETING → COMPLETED
UPLOADING → ABORTED / EXPIRED
COMPLETING → 核对后完成，或记录明确失败并补偿
```

- 同会话完成请求重复或并发执行，返回同一业务结果。完成前可返回处理中，不虚假宣布成功；版本创建和额度结算只能发生一次。
- 创建会话以原子条件更新预留配额，使用量与预留量之和不超过限制。完成转换为已用量，终止/过期释放；每会话只结算一次。
- 实际大小由存储端核对；与约定不符时不能静默增加配额或成功确认。校验机制按选定实现验证，不能仅信浏览器自报哈希。
- multipart 的 ETag 不能直接当整文件 MD5；恢复列表与完成请求的分片记录按所选 SDK/实现契约验证。[S3 官方机制说明](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)
- 存储完成与数据库提交不在同一事务。稳定 key、持久中间态和定期核对识别“文件有了，业务未落库”；核对具备重试期限、告警与人工可处理出口。
- `COMPLETING` 不能仅因请求超时就释放配额或删除对象；先确定存储与业务状态，再补偿。具体失败枚举和转换在 M2 契约中固定并测试。
- 过期清理须以状态/租约等条件避免与完成流程竞争，核对文件引用，不删除有效版本；multipart 残片也必须显式终止或按验证过的生命周期策略回收。
- 刷新后重新选择原文件可续传，须核对文件匹配；不承诺浏览器可以绕过用户授权重新读取本地文件。
- 首版不做跨用户秒传、跨空间去重和 CDN 上传加速。

## 4. 任务、消息与执行（M3–M4）

M3 的持久任务不依赖内存 Future 存续；M4 任务和 Outbox 同事务保存，由发布器发送到 MQ。发布确认、消费确认与业务完成是三个独立事件。结果持久化后才确认本次业务执行；持久任务扫描负责恢复，不依赖某条消息永久保留。

```text
QUEUED → RUNNING → SUCCEEDED
RUNNING → RETRY_WAIT → QUEUED
RUNNING → FAILED
QUEUED / RETRY_WAIT → CANCELED
RUNNING → CANCEL_REQUESTED → CANCELED
```

- 发送失败留在 Outbox 重试；发送成功但确认/标记丢失允许重发。消费者验证任务身份和状态，避免重复发布业务结果，不宣称 exactly-once。[RabbitMQ 官方确认机制](https://www.rabbitmq.com/docs/confirms)
- 用短事务和条件更新认领，检查受影响行数；运行期间不持有数据库锁。任务唯一键不等同于每次执行唯一。
- 尝试具有租约、心跳和新 token。续租、完成、失败、取消与恢复均检查状态和执行身份；有效租约之外的旧执行者不能发布结果。时间比较优先使用统一数据库时间。
- 输出写入 attempt 专属路径；仅有效尝试以受保护的数据库更新发布最终引用。旧输出即使生成也不能覆盖新输出，之后按引用清理。
- 恢复扫描即使多实例运行，也通过条件更新协调。过期可重新调度；旧 worker 仍可能浪费一次计算，不能声称绝不重复计算。
- 取消接受必须持久化；取消与完成只允许一个合法转换获胜。取消已接受后，旧结果不能再将任务改成成功。
- 临时故障有限退避重试；损坏媒体等永久失败归档。手动重试的权限、允许来源状态与次数在 M4 固定，保留尝试历史，不能随意复活成功或已取消任务。
- 重复消息遇到运行中任务时，不并行执行；确认/延迟策略必须与持久恢复方案配合验证。按所锁 MQ 版本核对消费确认超时和最大任务时长。
- 并发转码数、prefetch、排队量、输入大小、超时、临时磁盘和日志均有上限；不能使用无限队列掩盖过载。

FFmpeg/ffprobe 通过参数数组与 `ProcessBuilder` 启动，服务端生成工作目录与路径，不把用户文件名或媒体文本拼入 shell。读取并限制子进程输出，处理退出码、超时、中断与关闭；取消终止进程树，异常后清理临时资源。worker 使用必要权限与受限运行环境，组件版本须维护更新。

## 5. 权限、审核、分享与进度

- 同站 Web 默认 Spring Security 会话认证；M1 单实例，M6 Spring Session + Redis。使用成熟密码编码器，HTTPS 下配置 Secure、HttpOnly 和合适 SameSite；写请求保留 CSRF，不平行建设 JWT 登录。[Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)
- 查询、修改、签名、后台重试与 SSE 都校验当前成员身份和真实资源归属；版本、评论、审核等嵌套 ID 必须相互匹配，不能拼接其他空间 ID 绕过授权。
- 首版授权决定不缓存；成员撤销后不得继续通过缓存、搜索摘要、统计或推送暴露内容。SSE 订阅与后续推送维持同样边界。
- 审核的目标版本、轮次、素材修订号明确；审核、上传新版与审计写入按状态协调。无权、重复、过期或冲突各有明确反馈。
- 签名能力只覆盖指定对象、操作与短期限；分享签名期限不超过分享剩余期限。撤销阻止新签名，已签 URL 的剩余窗口必须文档化并测试。
- 对象默认私有，浏览器不持长期存储凭据。评论、文件名作为文本渲染；类型、大小、时长与实际媒体检查共同约束输入，不能仅信扩展名或请求头。
- SSE 只提示进度，重连/刷新先查询持久状态；用单调修订号避免倒退。连接、订阅与查询频率有界，无订阅时不为页面持续查询。转码百分比不表示精确剩余时间。

## 6. 缓存、搜索与 AI 的边界

M6 Redis 只承担共享会话、按用户/空间限流和一个素材元数据缓存场景。Lua 先选一种算法验证多实例行为；缓存用提交后失效等明确策略，固定 TTL/陈旧窗口，先鉴权再返回缓存内容。配额与任务正确性不依赖 Redis。

Redis 故障时：会话无法验证则拒绝受保护操作；元数据回源有并发上限；高成本上传/签名接口默认拒绝或保守本地限制，M6 选定一种并验证，不静默无限放行。

v1.1 搜索先建立 MySQL 固定数据基线。索引带空间、资源、单调实体修订号与删除标记，忽略旧事件，有重试和全量重建；权限过滤发生在展示正文、摘要、高亮和聚合之前，不能依赖滞后索引决定是否仍有成员权限。

v1.2 只选一条字幕→时间戳→检索片段→引用跳转链路。实时权限由后端执行，素材/字幕/检索内容是数据，不具工具权限；默认只读，不自动审核、删除或公开分享。与关键词检索或直接提供字幕比较，用约 20–30 条人工样例验证有答案、无答案、跨空间、旧版本及错误时间戳；记录引用、无依据断言、延迟与用量，费用另行授权。
