# 学习协作与 AI 分工

本约定把项目交付和后端能力增长放在一起，避免 AI 包办核心设计，也避免把学习变成执行障碍。只保存与本项目协作有关的偏好，不复制私人背景。

## 1. 主线与能力事实

MediaDesk 是当前主项目，TaskFlow 保留为基础实践参考，不要求继续扩展旧项目才允许开工。较旧学习总览中的 JDBC 阶段和主项目名称不覆盖较新的 MediaDesk 规划。

规划记录 TaskFlow 已有 REST、MyBatis、事务及部署实践；这是所读记录提供的起点，本次未重跑旧项目，不能等同于已经独立掌握全部机制。新任务先从实际代码和用户反馈判断缺口，已有基础不重新从头跟完整课程。

项目结果与学习结果分别成立：代码可以由 AI 协助完成，用户仍可通过后续关键修改、故障定位与解释建立能力。不得把 AI 参与自动算作成果无效，也不得把代码存在自动写成用户已掌握。

## 2. 选择协作方式

用户当前明确选择逐步引导式学习：从项目起点推进，细致讲清眼前问题。2026-10-19 用户要求提高每轮信息量，减少等待和零碎往返：把属于同一个业务环节的原理、完整示例、失败边界和下一步合在一轮，必要时只留一个有实际价值的动手点；已经回答正确的判断不再反复确认。解释采用第一性原理：先明确目标、事实、约束和必要条件，再推导最小方案，并用失败反例或实验检查；不以惯例或技术名称代替理由。细致程度服务于理解，不一次展开后续全部知识。后续用户明确要求直接实现时，仍按该次授权执行。

每次回答先回应当前问题，再实际推进一个当前范围内的步骤，或明确下一步由谁做、做什么、产出是什么。不要只确认理解后停住，也不要反复停留在同一知识点；引导提问应服务于新的判断或实际动手。

| 用户当前意图 | AI 应做什么 | 当前任务何时结束 |
| --- | --- | --- |
| 问概念、原因、比较 | 先回答具体问题，再给最小例子，按需要连接项目 | 问题已解释；不自动变为实施计划 |
| “我来写”“带我做”“给提示/评审” | 明确输入输出和边界，给局部提示，检查已有尝试，留一个动手点 | 指导请求已完成，说明等用户完成的部分 |
| “直接实现”“帮我完成/修好”或明确的实施任务 | 检查上下文，完成已授权实现和验证，解释核心取舍 | 任务完成或准确说明实际阻碍；不能只交建议 |
| 本次这类规划/规范请求 | 交付可使用的规范和状态入口 | 文档完成并检查；不自行开发应用 |

不要求每次开工选模式。根据表达合理判断；常规可逆选择直接推进。只有未决事项会明显改变正确性、范围、成本或难逆结果时询问。用户明确要求直接实现时，不把练习或口试作为门槛。

## 3. 核心工作分工

| 用户优先亲手实践 | AI 可以承担更多 |
| --- | --- |
| 业务规则、首批核心表结构、关键 SQL | 方案对照、解释约束、审阅 SQL 与缺口 |
| 上传完成和配额的事务/幂等 | 局部提示、失败窗口分析、故障脚本和代码评审 |
| 任务认领、心跳、取消、恢复、执行 token | 模型解释、竞争复现、测试建议和排错 |
| 资源授权与版本审核的关键修改 | 越权案例、接口契约核对、实现审阅 |
| 运行/解读关键实验，解释结果局限 | 整理日志、核对统计、撰写证据和说明 |
| 需求变化后的关键设计调整 | 重复表单、页面样式、样例、脚手架和工具脚本 |

这是默认的学习机会分配，不是文件写入禁令。AI 接到明确实现任务后可完成核心逻辑，交付时指出最值得理解的一两个决策；后续需要独立实践时再选择一个小改动，不追加整套返工任务。

## 4. 学习深度和停止线

“核心”意味着最终能够在允许查资料的情况下独立实现、验证、排错和解释，不要求背诵框架源码。辅助知识只需满足当前使用，不把每个组件学到相同深度。

| 内容 | 当前目标与可观察停止线 | 暂时略过 |
| --- | --- | --- |
| Java / Spring Boot / MyBatis | 能独立写请求链路、参数校验、SQL、事务与错误处理 | 重复基础课程、框架源码 |
| MySQL | 能设计约束/索引，解释条件更新与回滚，读实际 EXPLAIN | 内核、分库分表 |
| Spring Security / Flyway | 会配置并验证登录/退出/CSRF、新库迁移；资源授权须独立解释 | 自写密码学、双认证方案 |
| 上传与 S3 | 能解释会话、分片、签名、配额和部分成功，并验证续传/重复完成 | 存储集群、跨用户秒传 |
| MQ / JUC / 进程控制 | 能实现并解释确认、幂等、租约、恢复、取消及有界资源 | 手写线程池、通用调度平台 |
| FFmpeg / SSE | 会受控启动、超时/取消/清理、鉴权重连和状态补查 | 编码算法、多清晰度平台 |
| Redis | 能验证共享会话、一种限流和一个缓存策略的并发/故障边界 | 全数据结构打卡、集群/哨兵 |
| Vue / TS | 能修改组件/路由/请求/状态，完成表单与异常反馈 | 自建组件库、复杂动效 |
| 测试 / Docker / Linux / 监控 | 能复现运行、注入故障、定位和解释指标、恢复备份 | K8s、全套运维平台 |
| ES / AI | v1.0 后按功能学习搜索一致性或引用/权限/成本 | 现在预学、多 Agent、微调 |

陌生主题先解释“眼前哪个问题”，再做最小例子，最后说明机制与项目落点。可以先用简短视频建立整体地图；API、配置与边界查所选版本官方文档。模型清楚后尽快回项目，不连续更换整套课程。

每次解释自然交代：为什么现在学、从哪里开始、达到什么行为即可停止、哪些以后再看。达到范围时明确可以往前走；异常包装等局部细节不自动扩展成新课程。

## 5. 时间与基础线

规划按每周约 10 小时主项目时间估算，不是必须完成的周配额；阶段容量包含针对性学习、实现与验证。M2、M4 后根据实际投入校准，不用旧日期制造落后感。

CSAPP 和算法保留独立时段，不要求每天所有主线都做。项目遇到 IO、网络、进程、线程、内存和资源问题时再连接对应机制，不要求先学完整本教材。投递前另安排 JVM/GC/类加载与常见并发知识第一轮，但不自动塞入每次项目任务。

AI 扩展使用部分既有项目时间；不增加新的每日必做线。v1.0 后即可准备简历和面试，ES/AI 不作统一投递门槛。

忙碌时可以缩小任务、暂停或休息，不要求补回每个漏掉的时段。状态好时多做的工作不自动变成新最低标准；笔记、实验和验收不成为强制日报或每日考试。

## 6. 最小学习记录

重要节点只需保存三件事：为什么这样做、出现过什么失败、如何验证。已有 ADR 或实验能表达时直接引用，不另抄一份。

需要判断掌握时区分“看过/讨论过”“AI 或用户已实现”“验证已通过”“用户独立修改/解释有证据”；不维护强制逐日评分表，不由 AI 凭印象升级。

每个工作时段结束留一个具体接续点，例如“完成接口已做到幂等，下一步复现存储成功但数据库写入失败”。HANDOFF 保存工程事实；聊天中的私人感受与背景不写入公开仓库。
