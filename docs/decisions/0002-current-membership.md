# ADR-0002：成员表只保存当前关系

日期：2026-10-20
状态：已采用为 M0 设计基线，接口与并发机制待 M1 实现验证。

## 问题与约束

现有三表以用户/空间联合主键表达唯一当前关系，并用生成列唯一索引限制最多一个 Owner。需要明确移除和重新加入，而不让旧成员记录继续授予权限。首版不转移所有权；评论、审核等后续内容必须保留稳定作者身份。

## 决定与替代

采用最小方案：移除删除 Membership，保留 User 与业务内容；新邀请被本人接受后新建当前关系，角色取新邀请。Owner 不可移除、降级或退出。待接受旧邀请在移除事务内失效，已接受邀请不可再次创建成员。历史行为记录引用 User，M5 审计独立保存，不从旧 Membership 授权。

最强替代是带任期 ID、有效状态和修订号的历史成员模型，能表达多次加入并阻止旧页面请求作用于新任期，但需要额外字段、有效关系唯一性和所有查询的状态过滤。当前不要求完整任期时间线，先保留现有三表，不为该能力改表。

## 失败边界与证据

邀请接受与成员管理先锁同一 Workspace 行，在短事务内重查权限和状态；移除关系与旧邀请失效共同提交。所有入口必须遵守相同顺序，避免旧邀请在移除后恢复权限。角色修改/删除的条件禁止操作 Owner。

用户反馈 DEVELOPMENT 4.2 的查询、重复成员、第二个 Owner、非法角色和回滚实验符合预期；该证据不覆盖本 ADR 的 API 或并发机制。M1 需验证 Owner 保护、跨空间授权和移除/接受竞争，不能把本设计当作实现通过。

首版 PATCH/DELETE 针对当前关系，不承诺跨退出/重新加入的旧请求隔离；界面超时先刷新，不自动重放。完整任期审计、旧请求隔离或成员写吞吐出现明确需求时重开此决策。规则入口见 PRODUCT 2.1、ARCHITECTURE 第 2 节和 DEVELOPMENT 3.3。
