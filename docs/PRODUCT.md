# 产品范围与阶段门槛

状态：开发基线，非实现声明。依据 2026-10-18 规划 v1.0；当前进度只见 [HANDOFF](../HANDOFF.md)。

## 1. 从实际需要出发

一个小团队需要共同审阅图片和视频，并能确定“意见针对哪个版本、谁批准了哪个版本、交给外部的究竟是哪一份”。因此产品必须打通一条真实流程：

创建空间 → 上传素材 → 生成私有预览 → 对固定版本批注 → 上传新版 → 提交审核 → 通过或要求修改 → 分享通过的固定版本。

同时满足三类结果：用户能够完成流程；后端在重复请求、越权和部分失败时仍可信；开发者有可解释的设计与真实实验。增加技术名称本身不算结果。

### 1.1 首个可执行场景：两人审阅活动宣传片

M0-1 场景基线，已与 3.1 的五张文字草图作跨页面文档核对（见 3.2）；以下操作尚未实现。测试前提是小李与小王已有各自可登录的测试账号，账号来源和最简邀请的具体契约在 M0-2 固定。小李是本空间的 Owner，小王加入后是 Reviewer；访客只通过分享访问指定版本。

| 顺序 | 操作者与动作 | 系统必须记住的事实 | 页面应反馈 |
| --- | --- | --- | --- |
| 1 | 小李登录并创建“活动宣传”空间 | 空间及小李的 Owner 成员关系 | 进入新空间，素材列表为空 |
| 2 | 小李邀请小王，小王接受并以 Reviewer 加入 | 当前空间内小王的成员关系及角色 | 成员列表可见小王，小王可进入该空间 |
| 3 | 小李上传宣传片初稿 | 一份素材及固定版本 V1，原文件归属；上传完成与预览处理状态分别记录 | 原文件确认保存后，显示预览准备中 |
| 4 | 系统生成 V1 的预览 | V1 的处理结果及预览引用 | 预览确认可用后显示播放器 |
| 5 | 小王在 V1 的 00:12 留下“字幕有错” | 批注绑定 V1，位置为 12000 毫秒，保留作者与内容 | V1 的批注区显示该意见 |
| 6 | 小李提交 V1 审核，小王要求修改 | 目标为 V1 的审核轮次与结论 | V1 显示要求修改，保留批注与审核记录 |
| 7 | 小李上传修改后的 V2 | 同一素材下的新版本及新原文件，V1 保留 | 可切换 V1/V2，V2 不混入 V1 的批注；预览先显示准备中 |
| 8 | V2 预览就绪后，小李提交 V2 审核，小王批准 | 目标为 V2 的新审核轮次与通过结论 | V2 显示审核通过，V1 历史仍可查看 |
| 9 | 小李为 V2 创建限时分享，本场景选择仅预览 | 分享固定到已通过的 V2，保存能力、期限和撤销状态 | 显示交付版本、期限及分享入口 |
| 10 | 访客打开有效分享 | 访问依据是该分享的当前状态与能力 | 只提供指定 V2 的预览，不展示空间素材列表或其他版本 |
| 11 | 小李撤销分享 | 分享已撤销 | 后续分享访问与新签名被拒绝；已签 URL 的剩余有效窗口见既有规则 |

本场景采用两人分工以验证协作；Owner 仍可按既有权限独立完成全流程。分享固定到 V2，后来上传 V3 不会使此分享自动指向 V3。

场景的异常检查位置：

| 情况 | 应表达的位置与结果 |
| --- | --- |
| 未登录或会话过期 | 登录入口/当前页面提示重新登录，受保护 API 拒绝访问 |
| 其他空间用户尝试进入 | 空间入口或资源页面不披露内容，服务端按统一契约拒绝 |
| 上传中断 | 上传中心显示中断与恢复入口；恢复时重新选文件并核对 |
| 原文件已保存、预览未就绪 | 素材列表与详情显示预览准备中，不能宣布已可播放 |
| 原文件完好、预览因临时故障失败 | 详情/处理记录说明预览生成失败；按重试权限与来源状态提供后续操作，复用原文件；具体重试契约在对应阶段固定 |
| 上传新版与审核操作竞争 | 详情/审阅区提示冲突及刷新指引，不自动把操作改投其他版本 |
| 分享到期或撤销 | 访客页提示分享已失效，停止提供新签名，不展示资源内容 |

## 2. 角色与规则

v1.0 一个 workspace 同时承担团队和项目空间职责，不另建组织层级。第一版不转移所有权。

| 能力 | Owner | Editor | Reviewer | 外部访客 |
| --- | --- | --- | --- | --- |
| 查看空间内可访问素材和历史版本 | 是 | 是 | 是 | 仅有效分享指定版本 |
| 上传素材/新版，修改素材信息 | 是 | 是 | 否 | 否 |
| 评论及时间点批注 | 是 | 是 | 是 | 否 |
| 提交版本审核 | 是 | 是 | 否 | 否 |
| 批准或要求修改 | 是 | 否 | 是 | 否 |
| 邀请、移除、调整成员角色及配额配置 | 是 | 否 | 否 | 否 |
| 创建、撤销交付分享及删除/恢复素材 | 是 | 否 | 否 | 否 |
| 下载 | 成员权限内 | 成员权限内 | 成员权限内 | 分享显式允许才可下载 |

分享和删除权限采取 Owner 专有的初始保守默认，可在实际协作需求出现时通过契约变更调整。Owner 可以独立完成全流程；不增加双人审批门槛。客户端不得自行授予角色，不能移除或降级唯一 Owner。

产品不变量：

- 新版不覆盖旧文件；评论与审核绑定明确版本，不自动迁移到新版。
- 一个素材同时最多一个活动审核轮次。提交审核、审核结论与上传新版按素材状态/修订号协调，竞争失败返回可恢复的冲突。
- 新版本需要独立提交审核，旧版本审核历史保留。分享固定到审核通过的版本，不跟随“当前版本”跳转。
- 对外访客只读；下载与预览能力分别受控。预览可以被截图/录屏，不能承诺 DRM 或阻止一切复制。
- 删除先隐藏，保留期内可恢复，之后异步清理；有有效引用的文件不物理删除。隐藏/删除资源不再接受新的业务访问和签名。
- 成员被移除后，后续 API、签名与 SSE 数据访问依据当前权限拒绝。已发出的短期对象 URL 仍存在剩余有效期，不能承诺撤回已下载副本。
- 规划未定义且会影响权限或数据含义的规则，实施前形成明确契约；不得通过代码中的偶然行为决定产品语义。

## 3. 媒体、页面和体验范围

首批支持 JPEG、PNG 和常见 MP4；实际可处理的编码组合通过样例验证，并向用户提示不支持的格式。先保留原文件、生成封面和一套 MP4 预览；HLS 与多清晰度后置。

单文件字节数、视频时长、配额、分片并发、worker 并发、临时磁盘预算等配置在 M0 根据机器实测确定；不能预填承诺容量。开发用小样例不代表系统已经验证大文件能力。

| 页面 | 必须能完成 | 必须表现 |
| --- | --- | --- |
| 登录与空间入口 | 登录、退出、切换空间 | 登录过期、无权限、空空间 |
| 素材库 | 列表/网格、标签筛选、稳定分页、进入素材 | 加载、空结果、删除后刷新 |
| 上传中心 | 选文件、进度、取消、恢复 | 中断、配额不足、不支持的文件 |
| 素材详情 | 元信息、预览、版本切换 | 处理中、失败、版本不可访问 |
| 审阅区 | 时间点评论、回复、提交和查看审核 | 评论属于旧版本、状态竞争 |
| 成员与分享 | 邀请、角色、固定版本分享 | 移除成员、分享过期、撤销 |
| 处理记录 | 查看任务、失败原因、按权限重试 | 永久失败、防重复提交、无权操作 |

页面可组合，不要求七套路由分别实现。采用成熟组件库与播放器，统一请求、表单、错误反馈和状态；先覆盖常见桌面尺寸，移动端能浏览。权限按钮改善体验，服务端决定权限。界面装饰不能阻塞完整流程。

### 3.1 M0-1 低保真草图（逐页形成）

当前已完成五张文字草图，并作跨页面文档核对（见 3.2）。这里的方框表达信息与操作位置，不表示已有前端实现。

**第 1 张：登录与空间入口，包含两个视图。**

```text
未登录：
┌──────────────────────────────────┐
│ MediaDesk                        │
│ 账号 [                         ] │
│ 密码 [                         ] │
│ [登录]                           │
│ 错误提示：账号或密码有误等         │
└──────────────────────────────────┘

已登录：
┌──────────────────────────────────┐
│ MediaDesk        小李  [退出]    │
│ 我的空间          [创建空间]     │
│ [待接受邀请]                     │
│ 活动宣传   Owner     [进入]      │
│ 空状态：暂无空间，可创建或接受邀请 │
│ 请求失败：暂时无法加载 [重试]     │
└──────────────────────────────────┘
```

空间列表、空状态与请求失败是不同情况下的显示，不同时出现。创建空间先展示名称输入与提交反馈，成功后进入该空间的空素材库。待接受邀请的内容与反馈见第 5 张，具体邀请契约在 M0-2 固定。

登录用于确定当前用户身份；空间列表与进入空间依据当前成员关系授权。服务端不能信任客户端传来的 userId 或角色，修改请求中的空间 ID 仍须校验权限。显示角色仅说明该用户在这一空间的角色。

**第 2 张：空间内素材库。**

```text
[返回空间列表]  活动宣传    [成员与分享]

素材库                             [上传素材]
标签 [全部 v]

┌────────────────────────────────────┐
│ [封面占位] 活动宣传片              │
│ 视频 · V2 · 预览准备中             │
│ [查看详情]                         │
└────────────────────────────────────┘

[上一页]                     [下一页]
```

草图采用的可逆默认：每份素材一张卡片，显示最新创建版本的标题、类型、版本号与预览状态；封面未生成时使用占位。点击详情打开卡片明确显示的版本，不因该版本未就绪而静默播放旧版；有权用户在详情页切换历史版本。正式版本选择与请求契约在 M0-2 核对。

上传入口按 Owner/Editor 权限显示，成员与分享管理入口按 Owner 权限显示；Reviewer 仍可查看列表并进入详情。服务端对查询、上传与详情分别验证当前成员关系和资源归属。预览就绪只表示可预览，不能展示成审核已通过。

| 页面情况 | 显示与后续操作 |
| --- | --- |
| 首次请求中 | 正在加载素材，不提前宣告空列表 |
| 列表为空 | 暂无素材；Owner/Editor 可上传第一份素材，Reviewer 看到等待上传的说明 |
| 标签筛选无结果 | 当前筛选没有匹配素材，可清除筛选 |
| 请求失败 | 暂时无法加载素材，提供重试 |
| 版本预览未就绪或失败 | 卡片明确显示该版本的状态，详情承接等待说明或失败原因及有权操作 |
| 删除后返回列表 | 按最新结果刷新，移除已隐藏素材，不继续提供其新的访问入口 |

标签筛选与分页的具体请求参数、排序及上限在契约阶段固定。上传入口连接第 3 张上传中心，详情入口连接第 4 张素材详情/审阅。

**第 3 张：上传中心。**

以下以 Owner/Editor 在当前空间新建一份视频素材为例；上传新版时还须明确已有素材目标。进度数字仅为草图示意，不表示容量或性能验证。

```text
[返回素材库]  活动宣传

上传中心
[选择文件]

┌──────────────────────────────────────┐
│ 活动宣传片.mp4                       │
│ 上传中  [############--------] 60%    │
│ [取消上传]                           │
└──────────────────────────────────────┘

完成传输后：
文件已发送，正在确认保存……

服务端确认完成后：
原文件：已保存
预览：准备中                  [查看详情]
```

浏览器传输进度、上传业务完成、预览可用是三个分别确认的结果。进度到 100% 后先显示正在确认保存；服务端核对对象并完成对应业务记录后，才显示原文件已保存和版本入口；预览完成前不显示已可播放。进入详情时使用完成结果返回的固定版本身份。完成请求重复时仍对应同一上传结果，不多建素材版本。

| 阶段或异常 | 页面显示 | 可用操作与边界 |
| --- | --- | --- |
| 尚未选文件 | 请选择图片或视频 | 选择文件；客户端初步检查类型和大小，服务端仍独立核对，限制值待实测 |
| 已选文件、尚未开始 | 文件名及待上传 | 开始上传或移除选择；服务端校验权限、限制及配额后才能继续 |
| 正在传输 | 上传进度 | 取消上传；进度不表示预览处理进度 |
| 传输中断或刷新后待恢复 | 上传中断，需要重新选择原文件 | 重新选文件并核对匹配后，复用真实存储端确认的成功分片；会话过期或文件不匹配时明确说明不能按该会话续传 |
| 正在确认保存或完成响应丢失 | 正在确认保存/正在核对上传结果 | 查询同一上传的持久状态，不能因超时直接显示失败、重建版本或声称已取消 |
| 请求取消、结果未确认 | 正在取消 | 可立即停止本地继续发送；待服务端确认终止后才显示本次上传已取消 |
| 取消与完成竞争 | 正在核对最终结果 | 若取消未被接受且上传已完成，按最终状态展示版本入口与说明，不自动删除已创建的版本 |
| 原文件确认保存、预览未就绪 | 原文件已保存，预览准备中 | 查看详情；上传取消入口结束，处理任务取消属于后续独立规则 |
| 类型/大小不支持或配额不足 | 具体可读原因 | 选择符合限制的文件，或由有权成员处理空间配额；不静默超额 |

恢复入口不承诺浏览器刷新后可以自动重读本地文件。分片核对、文件匹配、配额结算、取消与完成竞争及存储/数据库部分成功的具体实现和实验在 M2 完成；本草图只确定应表达的事实与操作位置。失败的预览处理由详情/处理记录承接，在允许重试时复用已保存原文件。

预览状态与审核状态分别显示：预览可播放不代表内容审核通过。元信息区展示文件类型及已核实的规格/时长；图片版本改用图片预览，评论仍绑定版本，不展示视频时间点控件。版本记录能切回 V1 查看其文件、批注和审核历史。

| 操作 | 可操作角色 | 需要明确的目标或条件 |
| --- | --- | --- |
| 查看预览、版本及审阅记录 | Owner / Editor / Reviewer | 当前成员有权访问，素材、版本与空间归属匹配 |
| 新建批注与回复 | Owner / Editor / Reviewer | 绑定选中的固定版本；视频时间点非负且不超过已验证时长；回复与父批注的版本一致 |
| 上传新版、修改素材信息 | Owner / Editor | 上传入口明确已有素材目标，原版本与文件保留；状态竞争由服务端裁决 |
| 提交所选版本审核 | Owner / Editor | 目标版本满足提交契约，素材最多一个活动审核轮次 |
| 批准或要求修改 | Owner / Reviewer | 明确目标版本与当前活动审核轮次，提交时再次校验状态和权限 |
| 创建交付分享入口 | Owner | 只针对已通过的固定版本，转到第 5 张管理分享 |

页面行为与异常反馈：

| 情况 | 显示与操作规则 |
| --- | --- |
| 切换 V1/V2 | 版本标题、预览、批注、审核共同切换；加载期间不把旧版内容标成新版，晚到的旧请求结果不得覆盖当前版本视图 |
| 切换时存在未发送草稿 | 提示留在原版本继续编辑，或放弃草稿后切换；不把草稿及其时间点自动迁到新版本 |
| 查看 V1 的旧批注 | 在 V1 视图保留原文与归属，不因出现 V2 自动划掉或声称已解决 |
| 预览准备中或失败 | 播放器区域显示具体状态；原文件已保存时明确说明，在允许重试的条件下提供重新生成预览入口 |
| 当前版本没有批注 | 显示此版本暂无批注，不展示其他版本批注充数 |
| 审核中/已有结论 | 显示本轮状态或历史结论，禁止把已有结论当作新轮次可重复操作的入口 |
| 发送/审核响应尚未确认 | 显示提交中，保留明确的版本目标；只有服务端确认成功后才更新已发送或已通过的显示 |
| 审核或上传新版竞争导致状态过期 | 提示操作冲突并刷新可安全披露的当前状态，不自动把原来的审核动作改投新版或其他轮次 |
| 版本不存在或当前已无访问权限 | 不显示该资源内容，按统一契约提示并提供返回入口 |

所有查询与操作都必须携带足以确定目标的版本身份；审核还须明确轮次与并发校验依据。实际接口、状态枚举、允许审核的来源状态和竞争处理在对应契约阶段固定并验证，按钮隐藏/禁用不能替代服务端检查。

**第 5 张：成员与交付分享，包含 Owner 管理视图和访客视图。**

成员操作以邀请已有账号加入当前空间为草图方案，具体账号来源、邀请载体、身份核对、有效期与重复接受行为在 M0-2 固定，不由草图暗定接口。受邀用户登录后的空间入口提供“待接受邀请”：查看空间与拟授予角色，接受后刷新空间列表；页面请求失败时保留可重试反馈，不直接显示已加入。

角色属于用户在具体空间的成员关系。同一用户可以在另一空间拥有不同角色。只有当前 Owner 可邀请、调整角色或移除成员；首版不提供所有权转移，唯一 Owner 不提供移除或降级操作，服务端同样拒绝违规请求。移除成功后刷新成员列表，后续受保护 API 依据新的成员关系拒绝访问；已发出的对象短期访问地址仍受其剩余有效期约束。

创建分享时明确所选素材、已通过的固定版本、到期时间和下载能力。创建成功后向 Owner 提供可复制的分享入口；已有分享列表展示版本、能力、期限和状态。令牌发放、重复请求与再次展示入口的具体契约在 M5 固定，数据库只存令牌摘要，不在文档或日志中保存真实令牌和访问地址。

| 情况 | 页面反馈与边界 |
| --- | --- |
| Editor/Reviewer 尝试管理成员或创建/撤销分享 | 不提供 Owner 管理操作；服务端仍独立校验并拒绝无权请求 |
| 邀请、角色调整或移除尚未确认 | 显示提交中，确认成功后刷新成员事实；失败保留说明与可用操作 |
| 目标版本尚未审核通过 | 提示该版本不能创建交付分享，服务端重新核对版本归属及审核事实 |
| 分享创建请求尚未确认 | 显示创建中，不把临时占位显示成有效分享；重复处理按 M5 契约返回明确结果 |
| 后来上传 V3 | 已有分享仍明确标记 V2，不随最新版本改变 |
| 访客访问有效分享 | 服务端校验当前分享及资源状态，只提供指定版本和允许的能力，不显示空间列表、其他版本或内部批注 |
| 分享允许下载 | 访客视图按能力增加下载入口；每次获取访问能力仍经服务端核对 |
| 撤销请求尚未确认或结果未知 | 显示撤销中/正在核对结果，查询当前状态后再显示已撤销，不因点击即宣布撤销成功 |
| 分享已到期、撤销或资源不可访问 | 失效页不展示素材内容，服务端不再提供新的访问签名 |

撤销阻止后续业务访问与新签名，已发出的短期对象 URL 可能在剩余有效期内仍可用；签名期限不超过分享剩余期限。不能承诺收回已下载文件或截图。具体期限数值及撤销窗口在 M5 验证。

### 3.2 M0-1 跨页面核对（文档级）

2026-10-18 对照 1.1 的操作顺序及第 2 节角色表，人工走查五张文字草图。下表记录设计中已有的操作位置和反馈，不是浏览器测试或 API 验收。

| 场景与边界 | 草图中的接续位置 | 文档核对结果 |
| --- | --- | --- |
| 登录、创建空间、进入空素材库 | 第 1 张 → 第 2 张 | 已覆盖当前身份、空间成员授权、加载/空/失败及创建入口 |
| Owner 邀请 Reviewer 并加入 | 第 5 张成员管理 → 第 1 张待接受邀请 → 第 2 张 | 已覆盖邀请与接受位置，正式契约明确留待 M0-2 |
| 上传 V1、确认保存、等待预览 | 第 2 张上传入口 → 第 3 张 → 第 4 张 | 已区分传输、业务确认与预览结果，中断恢复与取消反馈有位置 |
| V1 时间点批注与要求修改 | 第 4 张 | 已覆盖版本/时间归属、提交审核、Reviewer 结论及历史保留 |
| 上传 V2、切换版本、独立审核 | 第 4 张上传新版 → 第 3 张 → 第 4 张 | 已保留 V1，V2 单独处理与审核，切换、旧响应与竞争不改投目标 |
| 通过 V2 后创建分享并交付 | 第 4 张 Owner 分享入口 → 第 5 张管理/访客视图 | 已覆盖固定版本、期限、显式下载能力及访客只读范围 |
| 分享到期或撤销 | 第 5 张管理 → 第 5 张失效视图 | 已区分请求与确认，记录短期对象 URL 的剩余窗口 |
| Editor、其他空间用户及唯一 Owner | 角色表及五张草图的服务端约束 | Editor 可上传/提交但不能批准或管理分享；其他空间用户拒绝；唯一 Owner 受保护 |

M0-1 的场景与草图交付到此完成，可接续 M0-2 首批模型与请求/响应契约。账号来源和邀请细节、版本选择与接口表示在 M0-2 形成可实现约定；资源限值在 M0-3 实测；上传、恢复、审核竞争及分享撤销的机制和真实实验仍按 M2–M5 推进。M0 环境、骨架和应用功能没有因本次文档核对而通过验收。

## 4. 版本与路线

| 版本 | 对用户的承诺 | 对应停止线 |
| --- | --- | --- |
| v0.1 产品样机 | 登录、空间、成员、基础上传、列表、私有预览 | M1 + M2 的最小成功链路；两人协作、空间隔离 |
| v0.2 可用产品 | 续传、媒体预览、版本、批注、审核、限时分享 | M5；上传到交付完整可演示，失败可处理 |
| v1.0 核心交付 | MQ 恢复、幂等、Redis、部署与真实实验 | M7；三项核心设计可解释，故障可重复验证 |
| v1.1 搜索增强 | ES 搜索、高亮和可靠索引同步 | v1.0 后按真实需要启动，验证乱序、删除和权限 |
| v1.2 AI，可选 | 字幕与时间戳检索，必要时带出处问答 | 独立确认范围与费用，有评估、权限和引用证据 |

阶段顺序服务于学习与风险控制。只完成当前阶段中用户授权的任务，不因拥有完整路线就自动执行后续阶段。用户明确要求调整顺序时说明依赖和影响；未完成的门槛继续如实保留。

| 阶段 | 参考容量 | 内容与退出条件 |
| --- | --- | --- |
| M0 契约与环境 | 6–10h | 场景、权限和版本规则、五个低保真草图；首批模型与请求/响应；版本/存储/资源短验证；最小骨架能从新环境构建，MySQL 和对象存储可连接；限制与命令有记录 |
| M1 身份与空间 | 12–18h | 会话登录/退出、空间、最简邀请、成员、迁移和基础页面；两用户同空间协作，跨空间拒绝，未登录与无权访问反馈明确 |
| M2 上传与素材库 | 18–28h | 小文件后再分片、续传、配额与私有访问；重新选文件可恢复；重复完成只有一个版本；并发配额不超额；存储/数据库部分成功可核对 |
| M3 媒体处理闭环 | 16–24h | ffprobe/FFmpeg 最小实验、单 worker、持久任务、封面、单规格预览和 SSE；成功、损坏、超时可追踪，刷新后能恢复状态 |
| M4 MQ 与恢复 | 28–42h | 分离 worker，Outbox、确认、认领、心跳、恢复、取消与基础指标；双 worker、重复消息、崩溃和旧 token 验证通过，资源有界 |
| M5 协作与交付 | 18–28h | 版本、时间点评论、审核、审计、站内提醒、分享与回收站；两用户走完核心流程，审核竞争、权限与撤销边界有证据；提醒先用查询/列表，不增加实时平台 |
| M6 Redis 与查询 | 12–20h | 共享会话、限流、一个元数据缓存场景；索引/分页核查；验证多实例与故障策略，记录缓存前后对比；无收益则调整，不能伪造优化 |
| M7 v1.0 交付 | 20–30h | Linux/Nginx、CI、监控、备份恢复、故障/性能报告、README 和演示；新环境复现，三项设计可解释，按真实贡献整理简历并开始追问练习 |

M0 子任务按顺序推进：M0-1 场景与草图 → M0-2 User、Workspace、Membership、Asset、AssetVersion 的首批契约 → M0-3 版本与存储短验证 → M0-4 最小工程。首批设计不要求一次迁移出所有表；M1 再实现身份与空间切片，M2 再建立上传所需实体。

总容量 130–200h，另留约 20% 弹性；按约 10h/项目周估算为 13–20 个项目周，均为估算而非日期承诺。M2、M4 后按实际耗时重估。v1.1 参考 18–30h，v1.2 参考 25–45h，不计入核心交付，也不自动叠加到每日学习任务。

## 5. 范围控制

当前不做：直播、在线剪辑、支付、公开内容社区、推荐、多区域容灾、原生移动端、自研编解码器、对象存储集群、K8s、跨空间去重。无双向实时协作需求不引入 WebSocket；进度优先 SSE。第一版不增加分布式 ID 服务、通用工作流引擎、两套登录或全套自建 UI 库。

新想法默认进入下一阶段候选，不插队。新增技术必须说明实际问题、现有方案不足和可验证收益；改变当前承诺、依赖顺序或成本时先与用户确认。扩展将推迟 v1.0 时优先交付核心版本。

新组件连续占用多次学习时段仍未服务核心流程时，先做最小隔离实验，依据结果调整。环境验证成本过高时可以暂停该组件选择，不能因此无限重选项目方向。

v1.0 验收后即可整理简历和模拟面试，不把 ES、AI、源码深挖或全部系统课程变成额外前置条件。项目完成与获得实习是不同结果，不作录用保证。
